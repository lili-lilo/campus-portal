## 0. 测试的定位

本项目的测试**不是质量指标，而是演示护栏**（A28 理由）：作品集需要一个"证明我写了测试"的最小证据 + 一条防止演示当天翻车的保险。

由此推出两条原则：

| 原则 | 含义 |
|---|---|
| **P-1 测得准 > 测得多** | 只测"错了会导致演示失败"的东西：状态机、权限、路由歧义、seed 幂等 |
| **P-2 不追覆盖率** | 不设覆盖率门槛（A28 明确不做），也不为此写无意义的断言 |
| **P-3 纯函数优先** | 状态机与权限判定必须写成纯函数（无 Prisma 依赖），使 L1 测试无需数据库即可在 CI 运行（裁决 ③，见 §3.3 与 T1.9 的 DoD） |

### 2.1 演示链路 9 步（E2E 全通）

来源：`01-项目定位.md` 演示链路 + `07-演示账号与链路.md`。

| # | 步骤 | 关键断言 | 可断言性 |
|---|---|---|---|
| 1 | 打开首页，看轮播、要闻、公告 | `/main` 返回 200；轮播至少 1 张图；要闻列表非空；公告标签可切换 | ✅ 完全可断言 |
| 2 | 点新闻详情，看富文本、附件 | 详情页含富文本 HTML 节点；附件列表至少 1 项且 `href` 指向 `/api/files/[id]/download` | ✅ 完全可断言 |
| 3 | 搜索"招生"，看高亮结果 | 结果数 > 0；命中片段含 `<mark>`；关键词被包裹 | ✅ 完全可断言 |
| 4 | 切换英文，看语言包 | 切换后 URL 变为 `/en/...`；导航文案变为英文 | ✅ 断言 URL + 文案（无需截图） |
| 5 | 打开无障碍，放大字体、高对比度 | 触发后 `<html>` 的 `data-a11y-font` / `data-a11y-contrast` 属性变化，且刷新后保持（持久化） | ⚠ **降级为冒烟**：断言属性与持久化，**不做视觉对比**（视觉回归明确不做） |
| 6 | 进后台登录，看仪表盘 | 登录成功跳 `/admin/dashboard`；统计卡片与图表容器渲染 | ✅ 完全可断言 |
| 7 | 新建文章 → 提交审核 → 初审 → 终审发布 | 状态依次为 `draft → pending_first → pending_final → published`；每次流转后 `AuditRecord` 增加 1 条 | ✅ 完全可断言 |
| 8 | 回前台看新文章 | **新文章出现在前台列表**（验证 `revalidatePath` 生效，A25 要求） | ✅ 完全可断言 |
| 9 | 切换子站，看独立首页 | `/cs` 返回 200；**页面不含全站轮播**（U7 简化模板）；标题含"计算机学院" | ✅ 完全可断言 |

> **第 5 步是唯一降级项**：无障碍面板的"放大字体/高对比度"本质是视觉变化，而视觉回归已明确不做。折中方案是断言**状态属性与持久化**，这能覆盖"开关是否生效、刷新是否丢失"两个真实故障点。
>
> **实现位置（M5-2b，2026-10-04）**：本步由 **`tests/e2e/a11y.spec.ts`（5 条）** 真跑覆盖 —— ① 无 cookie 默认 `100`/`off`；② 字号 5 档逐档点击后 `<html data-a11y-font>` 同步变化；③ 高对比度 `on` ⇄ `off`；④ **刷新保持 + SSR 首帧双证**（`reload()` 后属性仍 `150`/`on`，且 `page.request.get("/main")` 的**原始 HTML** 已含 `data-a11y-font="150"` ⇒ 证明 cookie 由服务端读取、首帧即正确、无闪烁）；⑤ 控制台**无** React 19 `Encountered a script tag` 警告（M5-2a 删内联脚本的回归）。偏好载体 = **cookie**（`a11y-font-scale` / `a11y-contrast`），根 layout 用 `cookies()` 读后直接写 `<html>` 的 SSR 属性（`docs/00` §8 #51）。

### 2.2 审核流 8 条边全覆盖（单元 + E2E）

对应 `13-数据模型-v2.md` 缺口 7 的 8 条转移边。**每条边一个单元用例**（直接调状态机函数），E2E 只覆盖边 1/2/3/6/7。

| 边 | 起点 → 终点 | 触发 | 单元 | E2E |
|---|---|---|---|---|
| 1 | `draft → pending_first` | `submitForReview` | ✅ | ✅ |
| 2 | `pending_first → pending_final` | `reviewArticle(pass)` | ✅ | ✅ |
| 3 | `pending_final → published` | `publishArticle` | ✅ | ✅ |
| 4 | `pending_first → rejected` | `reviewArticle(reject)` | ✅ | — |
| 5 | `pending_final → rejected` | `reviewArticle(reject)` | ✅ | — |
| 6 | `published → withdrawn` | `withdrawArticle` | ✅ | ✅ |
| 7 | `withdrawn → pending_first` | `submitForReview` | ✅ | ✅ |
| 8 | 任意状态 → `draft` | `saveArticleDraft` | ✅ | — |

**必须同时断言的非法转移**（8 条边之外的组合一律拒绝）：

| 非法转移 | 期望 |
|---|---|
| `draft → published` | `INVALID_STATE_TRANSITION` |
| `rejected → published` | `INVALID_STATE_TRANSITION` |
| `published → draft`（不经 `withdrawn`） | `INVALID_STATE_TRANSITION` —— **例外**：`saveArticleDraft`（`13` §7.2 边 8「任意状态 → draft」）可达，且须先落版本快照（C3）。本行指"**除它之外没有动作能达成**"（T1.10 注明，见 `docs/00` §8 #46） |
| `withdrawn → published`（不经 `pending_first`） | `INVALID_STATE_TRANSITION` |

**5 条强制约束的测试**（`13` 缺口 7.4）：

| 约束 | 断言 |
|---|---|
| C1 每次状态变更写 `AuditRecord` | 每次流转后 `AuditRecord` 计数 +1，且 `fromStatus`/`toStatus` 正确 |
| C2 服务端比对 `fromStatus` | 传入过期 `fromStatus` → `INVALID_STATE_TRANSITION` |
| C3 `published` 编辑前落快照 | 编辑已发布文章后 `ArticleVersion` 计数 +1 |
| C4 `editor` 仅本人稿件 | 用 editor 操作他人稿件 → `FORBIDDEN` |
| C5 前台过滤 | 非 `published` 或 `deletedAt != null` 的文章不出现在前台列表与搜索 |

## 3. CI（GitHub Actions）

### 3.1 三件套

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `pnpm install --frozen-lockfile` | 严格按 lockfile，防版本漂移（`12` §4） |
| **1a** | **`pnpm prisma generate`** | ⚠ **必需**：Prisma Client 产物 `app/src/generated/` 被 `app/.gitignore:64` 忽略（T1.1 三重声明的正确做法）→ CI 克隆后**没有生成物**，不 generate 则 `typecheck` 报 `TS2307`（CI #1 的失败根因，见 `docs/00` §8 #47） |
| **1b** | `pnpm prisma db push` | **仅 `verify` job**：给 `seed-idempotency` 准备临时库（**无 migrations** ⇒ 用 `db push`；测试体内也会 push 一次，幂等重复）。按 `DATABASE_URL` 前缀自动选 schema：sqlite 轨写 `file:./prisma/ci.db`、postgres 轨写 service 容器 |
| **1c** | `node scripts/gen-sqlite-schema.mjs --check` | **双轨同步校验**（M6-5）：`prisma/schema.sqlite.prisma` 必须与 `prisma/schema.prisma` 只差 `provider` 行 ⇒ 防两轨漂移 |
| 2 | `pnpm typecheck` | `tsc --noEmit`，0 错误 |
| 3 | `pnpm lint` | `eslint`，0 error（warning 不阻断） |
| 4 | `pnpm test` | Vitest（unit + component） |
| 5 | `pnpm build` | **仅 `main` 分支 push 时跑；PR 不跑**（裁决 ②） |

> **为什么 PR 不跑 `build`**：`build` 与 `typecheck` 的失败面高度重叠，却显著拖慢 PR 反馈速度。
> **为什么 `main` 要跑 `build`**：主干必须保持"随时可部署"（主干安全）；Vercel 也会构建，但 CI 先拦一道能在合并前暴露问题，而不是等到部署失败。
>
> **工作流分两个 job**：
> - `verify`：步骤 1~4，**所有 `push` + `pull_request` 都跑**；**M6-5 起为矩阵 `track: [sqlite, postgres]`**（双轨都要绿：本地默认 SQLite、生产是 PG）
> - `build`：步骤 1 + 5，**仅在 `push` 到 `main` 时跑**（`if: github.ref == 'refs/heads/main' && github.event_name == 'push'`）

### 3.2 触发与并发

| 项 | 约定 |
|---|---|
| 触发 | `push`（所有分支）+ `pull_request`（目标 `main`） |
| 并发 | `concurrency` 按 分支+PR 分组，`cancel-in-progress: true`（省额度） |
| Node | 与 `package.json` 的 `engines` 一致：**24.x**（满足 Prisma 7 的 `>=24.0`） |
| 缓存 | pnpm store 缓存（`actions/setup-node` 的 `cache: pnpm`） |
| 环境变量 | CI 按轨取：sqlite 轨 `DATABASE_URL="file:./prisma/ci.db"`（**不需要** service）、postgres 轨 `postgresql://…campus_test`（service 容器）；**不需要** `AUTH_SECRET`（单测不启动服务） |
| **不跑 E2E** | 明确不做（太慢）；E2E 仅本地演示前跑 |

### 3.3 数据库依赖

| 层 | 是否需数据库 |
|---|---|
| 单元测试（状态机、权限、路由、日期） | **不需要**（纯函数，无 Prisma） |
| `seed-idempotency` | **需要**（CI 双轨都跑：sqlite 轨用 `file:./prisma/ci.db`、postgres 轨用 service 容器；`db push` 建表、幂等 upsert） |
| 组件测试 | 不需要 |
| E2E | 需要（本地 `dev.db`） |

> **设计约束**：状态机与权限判定必须写成**纯函数**（输入当前状态 + 角色 → 输出新状态或错误），这样 L1 测试无需数据库。这是让 CI 能在无 DB 环境下跑起来的前提，也是 T1.9 的实现要求。
