## 步骤 1：创建项目（用户执行）

```powershell
cd D:\workspace
pnpm create next-app@latest app --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-pnpm --yes --skip-install
```

**flag 逐项说明**（全部来自批次 A 实测的可用列表）：

| flag | 作用 |
|---|---|
| `app` | 项目目录名（同时作为包名） |
| `--ts` | TypeScript |
| `--tailwind` | Tailwind CSS（v4） |
| `--eslint` | ESLint |
| `--app` | App Router |
| `--src-dir` | 使用 `src/` 目录（与 `13`/`15` 的 `src/app/...` 路径一致） |
| `--import-alias "@/*"` | 导入别名（**不要省略，否则会转交互提问**） |
| `--use-pnpm` | 用 pnpm（会生成 `pnpm-lock.yaml`） |
| `--yes` | 跳过所有剩余交互，接受默认值 |
| `--skip-install` | **先不装依赖** —— 依赖由步骤 3 分组精确安装，避免默认安装的版本与我们钉的版本打架 |

- **预期输出**：`Success! Created app at D:\workspace\app`
- **失败怎么办**：
  - 报目录已存在 → `Remove-Item -Recurse -Force D:\workspace\app` 后重跑
  - 报 `Unknown option` → 把报错原文贴回，**不要自行删 flag 重试**
  - 报网络超时 → 确认 `pnpm config get registry` 是 `https://registry.npmmirror.com`

## 步骤 3：装依赖（用户执行）

> **严格分组、严格顺序**。不要合并成一条命令。

### 3.1 四个钉版本包（**必须带精确版本**）

```powershell
pnpm add next-auth@5.0.0-beta.32 @auth/prisma-adapter@2.11.3
pnpm add -D prisma@7.10.0
pnpm add @prisma/client@7.10.0
```

- **为什么必须钉**（`12` §3.1，实测依据）：
  - `next-auth` 的 npm `latest` 是 **v4.24.15** → 不钉会装 v4，写法完全不同
  - `prisma` 的 npm `latest` 是 **8.0.0-rc.19（预发布）** → 不钉会装 RC
  - `@prisma/client` 的 `latest` 是 7.10.0，但必须显式钉以防 CLI 升到 8.x 后错配
- **预期输出**：`dependencies:` / `devDependencies:` 写入上述精确版本
- **失败怎么办**：
  - `ERR_PNPM_NO_MATCHING_VERSION` → **极可能是镜像缺该版本**，见步骤 4 的回退方案
  - peer 冲突警告 → **不要加 `--force`**，把完整警告贴回

### 3.2 Prisma 驱动适配器 + PG 驱动

```powershell
pnpm add @prisma/adapter-better-sqlite3@7.10.0 @prisma/adapter-pg@7.10.0 pg
pnpm add -D @types/pg
```

- **⚠ 绝对不要执行** `pnpm add better-sqlite3`
- **原因**：`@prisma/adapter-better-sqlite3@7.10.0` 依赖 `better-sqlite3 ^12.6.0`，而 npm `latest` 是 **13.0.3**（跨大版本）。显式安装会把 13.x 提升为顶层依赖，造成冲突。让适配器自己解析到 12.x（实测应为 **12.11.1**）。
- **失败怎么办**：
  - 若报 `better-sqlite3` **编译失败** → 这是 **R3 风险**，把完整报错贴回（`12` §5 R3 有处置方案：确认 Node 在允许集内）
  - 若安装后 `pnpm list better-sqlite3` 显示 **13.x** → 贴回，需处理
