### 0.2 工作模式（重要）

**DSH 只做"生成 + 审查"，安装与 git 操作由用户在开发机执行。**

| 动作 | 在哪执行（**2026-10-02 修订**） |
|---|---|
| 读写 `docs/`、源码、配置文件 | **DSH**（工作区 `D:\workspace` 内） |
| `pnpm lint` / `pnpm typecheck` / `pnpm <script>` / `pnpm exec` | **DSH 内执行** ✅ 已实测 → 每步 DoD 当场自证，不再"预期通过" |
| registry 版本查询 | **DSH 内 `node` 原生 fetch**（临时 `.mjs`，勿用 `node -e`） |
| `pnpm install` / `pnpm add` | **用户开发机**（依赖树与 store 变更交开发机） |
| `pnpm prisma …`（generate / validate / migrate） | **待验**：本会话只实测了 `pnpm lint`/`typecheck`/`exec`；T1.4 首次执行前先做一次可用性验证 |
| `git` | **用户开发机**（DSH 无 git） |
| 起 `pnpm dev` 做目视验收 | **先问用户**再起（长驻进程按后台 job 管理） |
| 汇报规则 | 每步做完**停下**贴变更摘要；用户确认后再进行下一步 |

### 3.2 husky 方案 A（根级宿主）

**背景**：git 根在 `D:\workspace`，应用在 `app/`。husky 9.1.7 的 `index.js` **只检查 cwd 的 `.git`，不向上查找** → 在 `app/` 里跑 `prepare: husky` 会输出 `.git can't be found`。

**方案 A**：把 husky 宿主放在**仓库根**。

| 位置 | 内容 |
|---|---|
| `D:\workspace\package.json` | `scripts.prepare = "husky"` + `devDependencies.husky` |
| `D:\workspace\.husky\pre-commit` | `pnpm --dir app exec lint-staged` |
| `app/package.json` | `prepare: "husky"` **保留**（在 app 内空转，无副作用） |
| git 配置 | `core.hooksPath = .husky/_`（husky 自动写入） |

**三条必须知道的规则**：

1. **`core.hooksPath` 期望值是 `.husky/_`**，**不是** `.husky` 或 `D:\workspace\.husky`（husky 把 shim 放 `_/`，让 shim 回调 `.husky/<name>`）。
2. **`.git can't be found` 时 husky 的 exit code = 0** —— `prepare` **不会**让 `pnpm install` 失败，只是空转。**不要加 `husky || true`**（会掩盖真实错误）。
3. **⛔ 禁止运行 `pnpm exec husky init`** —— 它会 ① **覆盖 `.husky/pre-commit`** 为 `<pkg> test`；② **重写根 `package.json`**。首次配置只需 `pnpm install`。

**已验证**：拦截实测通过（探针含 `any` → `eslint --fix` 报错 → `husky - pre-commit script failed (code 1)` → commit 被拦）。

### 3.3 Prisma `env()` 写法（关键，曾写错）

**`prisma.config.ts` 的正确形态**：

```ts
import "dotenv/config";                                   // ← 必须保留
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  datasource: { url: env("DATABASE_URL") },               // ← 静态 string，不是函数
  migrations: { path: "prisma/migrations", seed: "tsx prisma/seed.ts" },
});
```

**三条实测依据**（`@prisma/config@7.10.0`）：

| 事实 | 出处 |
|---|---|
| `datasource.url` 类型是 **`string`**（`Datasource = { url?: string; shadowDatabaseUrl?: string }`） | `dist/index.d.ts` |
| `env(name)` 返回 `process.env[name]`，**缺失即抛 `PrismaConfigEnvError`**（fail-fast） | `dist/index.js` L515-521 |
| **Prisma 7 刻意不自动加载 `.env`** —— 加载 config 文件时传 `dotenv: false`（注释原文 *"do not load .env files"*） | `dist/index.js` L633-634 |

**❌ 曾写错**：`url: () => process.env.DATABASE_URL` → `migrate dev` 报 *"The datasource.url property is required in your Prisma config file"*（函数不满足 `string`，且 `process.env.X` 是 `string | undefined`）。

**另外**：`generator` 必须用 **`prisma-client`**（非 `prisma-client-js`）、**`output` 必填**；`datasource` 块**只写 `provider`**；运行时 Client **必须传驱动适配器**。

### 3.4 `next typecheck` 三步化（只清 `.next/dev/types`）

```json
"typecheck": "node -e \"require('fs').rmSync('.next/dev/types',{recursive:true,force:true})\" && next typegen && tsc --noEmit"
```

**为什么**：`next typegen` **只重新生成 `.next/types/`**，**不清理 `.next/dev/`**（后者属 `next dev` 产物）。而 `tsconfig.json` 的 `include` **同时收录** `.next/types/**/*.ts` 与 `.next/dev/types/**/*.ts` → **删掉一个路由后，陈旧的 dev 路由类型仍被 `tsc` 编译**，报 `Cannot find module '../../../src/app/<已删路由>/page.js'`。

**为什么只清 `.next/dev/types` 而不是整个 `.next`**：该目录是**唯一**既被 `include` 收录、又不会被 `typegen` 刷新的目录；整删会连带丢弃 Turbopack 缓存（数 MB），拖慢下次 `pnpm dev`。

**⚠ npm script 内联引号**：`node -e` 必须转义为 `node -e \"...\"`，内部字符串用**单引号**。已实测该片段可直接执行（exit 0、无输出、目标目录确被删除）。

**连带要求**：`next typegen` 会**以 production build 阶段加载 `next.config.ts`**，所以 **CI 跑 `typecheck` 时必须提供 `.env` 或注入变量**。

### 3.5 `carousel.tsx` 本地修改（必须保留）

`app/src/components/ui/carousel.tsx` 是 **shadcn 生成代码**，但已**本地修改**（T1.2，2026-10-02），原因有两层：

| 问题 | 说明 |
|---|---|
| **lint 报错** | React 19 的 `react-hooks/set-state-in-effect`（`eslint-plugin-react-hooks@7`）报 effect 体内同步 `setState` → 级联渲染 |
| **真 bug** | 原代码 `api.on("reInit", onSelect)` **注册了监听却未在 cleanup 取消**（只 `off` 了 `"select"`）→ **监听器泄漏** |

**修改内容**（2 处）：

```tsx
React.useEffect(() => {
  if (!api) return
  api.on("reInit", onSelect)        // 保留注册
  api.on("select", onSelect)
  return () => {
    api.off("reInit", onSelect)     // ← 新增（修泄漏）
    api.off("select", onSelect)
  }
```
