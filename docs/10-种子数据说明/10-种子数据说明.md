## 0. 两条硬要求

| 要求 | 内容 |
|---|---|
| **幂等** | 所有 seed 函数必须用 `upsert`，以确定性键为 `where`；**重复执行结果完全一致**（用户裁决）。禁止使用 `create`（会因唯一约束失败）或 `createMany`（无法保证幂等） |
| **密码哈希** | 所有账号统一密码 `admin123`，写入前用 **bcryptjs（rounds = 10）** 哈希（A29）；**禁止明文入库** |

**确定性 upsert 键一览**：

| 模型 | where 键 |
|---|---|
| `Site` | `slug` |
| `Channel` | `(siteId, slug)` |
| `Page` | `(siteId, channelId)` |
| `User` | `username` |
| `Role` | `code` |
| `Permission` | `code` |
| `RolePermission` | `(roleId, permissionId)` |
| `UserRole` | `(userId, roleId)` |
| `Article` | `(siteId, slug)` |
| `ArticleVersion` | `(articleId, version)` |
| `Media` | `path` |
| `Attachment` | `(articleId, fileName)` |
| `Statistic` | `(dateKey, siteId)` |
| `Form` | `name` |
| `Config` | `key` |
| `Comment` / `Message` / `FormData` / `Log` / `AuditRecord` / `Navigation` | 固定 id（`seed-<model>-<n>` 形式） |

> `Navigation` 虽无自然唯一键，但因使用固定 id，`upsert({ where: { id } })` 同样幂等。

## 1. 站点（4 个）

| slug | 名称 | 说明 |
|---|---|---|
| `main` | XX大学 | 主站 |
| `cs` | 计算机学院 | 子站 |
| `ee` | 电子信息学院 | 子站 |
| `ba` | 商学院 | 子站 |

`Site.domain` 可留空（本期用路径 `/[site]`，不做子域名，A21）。

## 2. 栏目

**主站（8 个）**：学校概况（`page`）、新闻中心（`list`）、通知公告（`list`）、院系设置（`list`）、师资队伍（`list`）、招生就业（`list`）、科学研究（`list`）、信息公开（`list`）

**子站（各 6 个）**：学院概况（`page`）、新闻动态（`list`）、师资队伍（`list`）、专业介绍（`list`）、科研成果（`list`）、联系方式（`page`）

> ⚠ **保留 slug 黑名单（A19）**：`news / notice / about / departments / faculty / admissions / research / disclosure / search / sitemap` 不得用作 `Channel.slug`。seed 生成栏目时**必须加断言**，命中即抛错终止，否则 `[channel]` 动态路由会被静态路由永久遮蔽。

**导航（`Navigation`）**：主站约 8 项 + 子站各约 5 项；`channelId` 指向站内栏目，或 `url` 指向外部链接（二者至少一个非空）。

## 3. 单页（`Page`，v1 缺失、本次新增）

| 站点 | 内容 |
|---|---|
| main | 学校简介、历史沿革、现任领导、组织机构、联系我们（5 篇） |
| cs / ee / ba | 学院概况（各 1 篇） |

`Page` 与 `Article` 分开：单页无作者/标签/评论/审核流，`status` 仅 `draft / published` 两态。

## 4. 文章（100 篇）

**分类分布**

| 分类 | 数量 |
|---|---|
| 学校要闻 | 30 |
| 通知公告 | 20 |
| 学术活动 | 15 |
| 招生就业 | 15 |
| 科研动态 | 10 |
| 党建思政 | 10 |

**站点分布**：主站 60 篇，子站各 10~15 篇。

**状态分布（6 态，取代原 `80/10/10`）**

| 状态 | 数量 | 用途 |
|---|---|---|
| `published` | 80 | 前台列表、搜索、统计 |
| `pending_first` | 6 | 演示"待初审"待办 |
| `pending_final` | 4 | 演示"待终审"待办 |
| `draft` | 4 | 演示"继续编辑" |
| `rejected` | 3 | 演示"退回修改"（`pending_* → rejected → draft`） |
| `withdrawn` | 3 | 演示"撤稿 / 重新提交"（`published → withdrawn → pending_first`） |

合计：`80 + 6 + 4 + 4 + 3 + 3 = 100`

> ⚠ **每种非 `published` 状态必须连带种出对应的 `AuditRecord` 流转轨迹**（`fromStatus`/`toStatus`），否则后台审核时间线是空的。
> 例：一篇 `pending_final` 的文章应有 2 条记录 —— `draft→pending_first`、`pending_first→pending_final`；一篇 `withdrawn` 的有 3 条。

## 6. RBAC（v1 缺失、本次新增）

| 模型 | 数量 | 说明 |
|---|---|---|
| `Role` | **4** | `super_admin`（`siteId=null`，全局）、`site_admin`、`editor`、`auditor`；均 `isSystem=true` |
| `Permission` | 约 20 | 三类：`menu` / `action` / `data` |
| `RolePermission` | 按角色矩阵 | 每个角色的权限勾选结果 |
| `UserRole` | 11 | 每用户 1 条，`siteId` 与 `User.siteId` 一致（`admin` 为 null） |

`Role.code` 与 `User.role` 字符串**取值必须一致**，保证"快速判断"与"细粒度权限"指向同一角色语义。

## 7. 媒体与附件

**媒体（50 条）**
- 使用 Unsplash 占位图或本地生成
- `folder`：`news`（新闻配图）、`carousel`（轮播图）、`dept`（院系图）、`leader`（领导照片）、`other`
- `album`：相册分组（如"校园风光"），与 `folder` 正交
- `siteId`：可空（空 = 全站共享）

**附件（约 20 条，v1 缺失、本次新增）**
- 挂在前 20 篇已发布文章上（`Attachment.articleId`）
- 含 `fileName` / `filePath` / `size` / `mimeType` / `downloadCount`
- 演示链路第 2 步"看富文本、附件"依赖它

## 9. 统计（90 天，按 A32 时区规则）

- **360 行** = 90 天 × **4 个站点**（`main` / `cs` / `ee` / `ba`）
- **不生成"全站汇总"行**：`Statistic.siteId` 是必填真外键，哨兵值会违反外键约束；图表需要"全站"时对 4 个站点求和（方案 A，见 `13` Q6）
- `dateKey` 格式 `YYYY-MM-DD`，**按 `Asia/Shanghai` 计算**：

```ts
dateKey = new Intl.DateTimeFormat("en-CA", {
  timeZone: "Asia/Shanghai",
  year: "numeric", month: "2-digit", day: "2-digit",
}).format(utcDate)   // en-CA 输出 2026-10-01
```

- `date` 字段存 UTC 零点，**仅供展示与排序，不用于聚合**
- 来源分布 `source`：`search` / `direct` / `external`

## 11. 种子脚本结构

由 `prisma.config.ts` 的 `migrations.seed` 指向，执行命令为 `pnpm db:seed`（即 `prisma db seed`）。

```typescript
// prisma/seed.ts
async function main() {
  // —— 站群骨架 ——
  await seedSites()            // 4 站点
  await seedChannels()         // 主站 8 + 子站各 6（含保留 slug 断言）
  await seedNavigations()      // 主站 8 + 子站各 5
  await seedPages()            // 主站 5 + 子站各 1

  // —— 权限体系 ——
  await seedRoles()            // 4 个系统角色
  await seedPermissions()      // 约 20 条
  await seedRolePermissions()  // 角色权限矩阵
  await seedUsers()            // 11 账号（bcrypt 哈希）
  await seedUserRoles()        // 11 条，与 User.role / User.siteId 一致

  // —— 内容 ——
  await seedArticles()         // 100 篇（6 态分布）
  await seedArticleVersions()  // 约 120 条
  await seedAuditRecords()     // 约 150 条（覆盖六态流转轨迹）
  await seedMedia()            // 50 条
  await seedAttachments()      // 约 20 条

  // —— 互动 ——
  await seedComments()         // 30 条（含 8 条回复）
  await seedMessages()         // 10 条
  await seedForms()            // 3 个
  await seedFormData()         // 30 条

  // —— 运维 ——
  await seedStatistics()       // 360 行（90 天 × 4 站点）
  await seedConfigs()          // 约 12 条
  await seedLogs()             // 约 40 条
}

main()
  .catch((e) => { console.error(e); process.exit(1) })
  .finally(async () => { await prisma.$disconnect() })
```

**不 seed 的表**：`Account` / `Session` / `VerificationToken` —— Credentials 流程不写入这三张表，它们仅为 Auth.js Adapter 兼容而存在。

## 12. 验收标准（T1.5）

| 项 | 标准 |
|---|---|
| 幂等 | `pnpm db:reset && pnpm db:seed` **连续执行两次，结果完全一致**（行数与关键字段均一致） |
| 完整性 | 4 站点 / 主站 8 栏目 + 子站各 6 / 11 用户 / 4 角色 / 100 文章 / 50 媒体 / 20 附件 / 30 评论 / 10 留言 / 360 统计 / 3 表单 / 30 表单数据 |
| 演示可用 | `07` 的 4 个账号均可登录；演示链路 9 步所需数据全部存在 |
| 密码 | 库中 `User.password` 均为 bcrypt 哈希（`$2` 开头），无明文 |
| slug | 无栏目使用保留 slug（断言通过） |
