### 1.1 三个路由组的边界

| 组 | 路径前缀 | locale | 布局 | 鉴权 |
|---|---|---|---|---|
| `(site)/[locale]/[site]` | `/`（默认 zh 不带前缀） | ✅ 有 | `SiteHeader` + `SiteFooter` | 公开 |
| `admin/` | `/admin` | ❌ 无（固定中文） | 后台侧边栏 + 顶栏 | 全部需登录 |
| `api/` | `/api` | ❌ 无 | 无 | 按 `14` §2.4 分层 |

> **后台不走 locale 的理由**：后台是内部工具，双语文案成本高且无人看；且 `/admin` 与前台 `[site]` 同级，若加 locale 段会出现 `/en/admin` 这种无意义路由。

## 2. 路由标注约定

下表与 §2.2 的每条路由都按 5 个维度标注：

| 维度 | 取值 | 说明 |
|---|---|---|
| **渲染** | `SSG` / `ISR` / `SSR` / `CSR` | SSG = 构建时静态；ISR = 静态 + `revalidate`；SSR = 每请求渲染；CSR = 客户端渲染 |
| **缓存** | `revalidate: N` | 对应 Next 的 ISR 秒数；`0` 表示动态 |
| **权限** | `公开` / `登录` / `权限码` | 权限码取自 `14-API契约` §7 |
| **数据源** | Server Action 函数名 或 Route Handler 路径 | 取自 `14-API契约` §3~§5 |
| **model** | `13-数据模型-v2` 的模型名 | 该页直接读取的模型 |

## 3. locale 段与 URL 形态（A21）

### 3.1 URL 规则

| 语言 | URL 形态 | 例 |
|---|---|---|
| `zh`（默认） | **不带前缀** | `/main/news`、`/cs/about` |
| `en`（非默认） | **带前缀** | `/en/main/news`、`/en/cs/about` |

**实现方式**：`next-intl` 的 `localePrefix: "as-needed"` 模式 —— 默认语言省略前缀，非默认语言强制前缀。

### 3.2 路由组与 locale 的组合

```
src/app/(site)/[locale]/[site]/...
```

- `(site)` 是**路由组**（括号不进入 URL），用于让前台共享一套布局，同时与 `/admin`、`/api` 隔离；
- `[locale]` 承接语言段；
- `[site]` 承接站点 slug（`main` / `cs` / `ee` / `ba`）。

**URL 到文件的映射**：

| 请求 URL | `[locale]` | `[site]` | 匹配文件 |
|---|---|---|---|
| `/main/news` | `zh`（默认） | `main` | `(site)/[locale]/[site]/news/page.tsx` |
| `/en/main/news` | `en` | `main` | 同上 |
| `/cs` | `zh` | `cs` | `(site)/[locale]/[site]/page.tsx` |
| `/en` | `en` | —（缺 site） | **不合法** → 404，或重定向到 `/en/main` |

### 3.3 根路径处理

| URL | 行为 |
|---|---|
| `/` | **302 → `/main`**（主站首页）。理由：演示链路第 1 步是"打开首页"，根路径必须直达主站 |
| `/en` | **302 → `/en/main`** |
| `/{未知 slug}` | 404（不重定向到主站，避免掩盖错误） |

### 3.4 语言包加载

| 项 | 约定 |
|---|---|
| 文件位置 | `src/i18n/messages/{zh,en}.json` |
| 范围 | **系统文案 + 主要页面**（`11` §2.2）；**文章内容不做双语**（`Article` 表无 `locale`/翻译字段） |
| 命名空间 | `common` / `nav` / `footer` / `home` / `news` / `search` / `accessibility` / `admin` |
| 缺失兜底 | 缺 key 时回落 `zh`，并在开发环境 console 警告 |

## 4. 保留 slug 与 `[channel]` 消歧

### 4.1 保留 slug 黑名单（A19）

静态路由已占用的 slug，**数据层禁止再用作 `Channel.slug`**：

```text
news  notice  about  departments  faculty  admissions  research  disclosure  search  sitemap
```

**为什么必须有这条规则**：Next.js 的文件路由中静态段优先于动态段，`/[site]/news` 永远会命中 `news/page.tsx`，`[channel]` 拿不到它。这不是可以"修"的 bug，只能让数据层不产生歧义。

### 4.2 三重保障（缺一不可）

| 层 | 时机 | 动作 | 失败表现 |
|---|---|---|---|
| **① 框架层** | 请求时 | Next.js 静态路由天然优先 | 无需干预 |
| **② 种子层** | `pnpm db:seed` | seed 生成 `Channel` 时加断言，命中黑名单**抛错终止** | 种子脚本失败，立刻暴露 |
| **③ 后台层** | 表单提交时 | zod 校验 + 友好提示"该名称已被系统页面占用" | 返回 `SLUG_RESERVED`（`14` §2.2） |

> **②是关键**：只在后台校验不够 —— seed 是绕过 UI 直接写库的，必须独立断言。

### 4.3 `[channel]` 四分支规则表（A20）

`[channel]/page.tsx` 按 `Channel.type` 分流，**一个动态路由吃下四种栏目类型**：

| `Channel.type` | 渲染内容 | 数据源 | 特殊处理 |
|---|---|---|---|
| `list` | 该栏目下的文章列表（分页、按 `publishTime` 倒序） | `listArticles` / `GET /api/articles?channel=` | 无文章时显示空态，不 404 |
| `page` | 取 `Page` 渲染单页正文 | `getPage` / `GET /api/pages/[site]/[slug]` | **该栏目无 `Page` 记录时 404** |
| `link` | 服务端 **302 跳转**到 `Channel.url` | `getChannelTree` | `Channel.url` 为空时 404（**已于 2026-10-01 补齐该字段**，见 `13` v2.2 / U1） |
| `form` | ——**本期不渲染**（`14` §8 A2 裁决） | — | 返回 404 + 提示"该栏目暂未开放" |

### 4.4 栏目级联与 `[channel]/[id]`

| 路径 | 含义 |
|---|---|
| `/[site]/[channel]` | 栏目的入口页（按上表四分支） |
| `/[site]/[channel]/[id]` | **`list` 型栏目**下的文章详情 |

> **与 `/[site]/news/[id]` 的关系**：`news` 是保留 slug（有专属静态路由），所以新闻详情走 `/[site]/news/[id]`；其它栏目（如 `academic`）的文章详情走 `/[site]/[channel]/[id]`。两者**读同一份 `Article` 数据、渲染同一个组件**，只是入口路径不同。

## 5. 根级拦截层（A22 + A39）

### 5.1 文件命名（✅ 已结案，2026-10-02）

| 项 | 内容 |
|---|---|
| **依据（官方随包文档）** | `app/node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` 首行：**"The `middleware` file convention is deprecated and has been renamed to `proxy`"** |
| **文件名** | **`proxy.ts`** —— 位于**项目根或 `src/`**（与 `app`/`pages` 同级）→ 本项目为 **`app/src/proxy.ts`** |
| **导出形式** | **名为 `proxy` 的函数**（或 `default` 导出）：`export function proxy(request: NextRequest) {...}` |
| **`matcher`** | 仍用 `export const config = { matcher: [...] }`（与旧 Middleware 一致） |
| **本项目职责** | ① locale 协商与重写；② `/admin/*` 会话存在性检查（详见 §5.2 / §5.3） |
| **回退**（保留未用） | 若 `proxy.ts` 与 next-intl / Auth.js 任一不兼容 → 改用"layout 内服务端鉴权 + next-intl 官方推荐写法"，并在 §8 登记原因 |

> ⚠ **不再有"待实测"项**：此前写作 `src/app/proxy.ts` 是**错的** —— 官方要求放在 `src/` 或项目根，**不是 `src/app/` 内**。本文档内其余位置若出现 `src/app/proxy.ts` 均以此表为准。`docs/11` A39 与 `docs/12` R7 已同步结案。

### 5.2 职责（二合一）

> **登录回跳的两个字段名（T1.10 补；实测依据 `next-auth@5.0.0-beta.32/lib/actions.js`）**：proxy → 登录页用查询参数 **`callbackUrl`**（登录页读 `searchParams`）；登录页 → Auth.js 用隐藏表单字段 **`redirectTo`**（Auth.js 从 `FormData` 读 `redirectTo`，**不读 `callbackUrl`**）。二者由登录页互转（失败回跳再转回 `callbackUrl`）。参见 `docs/00` §8 #39。

```ts
// 伪代码，非实现
export function proxy(request) {
  // ① locale 协商与重写（next-intl）
  //    - 读取 cookie / Accept-Language 决定 locale
  //    - 默认 zh 时内部重写到 /zh/...，但 URL 保持 /main/news 形态
  // ② 后台保护
  //    - 匹配 /admin/* 且非 /admin/login
  //    - 无有效会话 → 302 /admin/login?callbackUrl=<原路径>
}
```

### 5.3 鉴权分工（重要：拦截层只做两件事）

| 层 | 位置 | 做什么 | **不做什么** |
|---|---|---|---|
| **拦截层** | `proxy.ts` | ① locale 重写；② `/admin/*` 的**会话存在性检查**（cookie 有无 + 是否可解析） | ❌ 不查数据库权限、❌ 不判断数据范围 |
| **页面层** | 每个后台 `page.tsx` / `layout.tsx` | 完整会话校验（`auth()`） | — |
| **动作层** | 每个 Server Action | **三层校验**：L1 认证 + L2 权限码 + L3 数据范围（`14` §2.4） | — |

**为什么拦截层不查权限**：

1. **Next 16 起 proxy 默认 Node.js runtime**（`proxy.md` L255）—— 原稿"运行在 Edge Runtime、无法使用 Prisma"的论据**已过期**（见 `docs/00` §8 #33）；真正该守的是官方要求：**拦截层只做乐观校验**，只读 cookie、避免数据库查询（`authentication.md` L1033、`loading.md` L113）；
2. 即使能查，也会对每个 `/admin/*` 请求增加一次数据库往返；
3. **真正的安全边界在动作层** —— 拦截层只是体验优化（未登录时别渲染空壳后台）。

> **安全声明**：任何"仅靠拦截层保护"的设计都是错的。本项目的权威校验点是 **Server Action 内的 `requirePermission`**（`14` §2.4），拦截层被绕过也不影响安全性。

### 5.4 匹配范围

| 匹配 | 处理 |
|---|---|
| `/api/auth/*` | **必须排除**（否则登录回调死循环） |
| `/api/*`（其余） | 排除（Route Handler 自行鉴权） |
| `/_next/*`、`/favicon.ico`、静态资源 | 排除（`.matcher` 配置） |
| `/admin/login` | 排除（否则未登录无法进入登录页） |
| `/admin/*`（其余） | 会话存在性检查 |
| 其它一切（前台） | locale 协商与重写 |

## 6. 前台路由表（逐条标注）

> 所有前台路由均为**公开**访问（无需登录）。权限列固定为 `公开`，故下表省略该列；改为标注渲染策略与数据源。

| 路径 | 渲染 | 缓存 | 数据源（`14`） | model |
|---|---|---|---|---|
| `/` | — | — | **302 → `/main`**（U4 裁决） | — |
| `/[site]` 首页 | **ISR** | `revalidate: 300` | `listArticles(top/recommend)`、`listMedia(folder=carousel)`、`getChannelTree`、`listNavigations` | `Article`、`Media`、`Channel`、`Navigation` |
| `/[site]/news` | **ISR** | `300` | `listArticles({channel:'news'})` 或 `GET /api/articles` | `Article`、`Channel` |
| `/[site]/news/[id]` | **ISR** | `300` | `GET /api/articles/[idOrSlug]` | `Article`、`Attachment`、`Comment` |
| `/[site]/notice` | **ISR** | `300` | `listArticles({channel:'notice'})` | `Article` |
| `/[site]/about` | **ISR** | `3600` | `GET /api/pages/[site]/about` | `Page` |
| `/[site]/about/history` | **ISR** | `3600` | `getPage` | `Page` |
| `/[site]/about/leaders` | **ISR** | `3600` | `getPage` | `Page` |
| `/[site]/about/organization` | **ISR** | `3600` | `getPage` | `Page` |
| `/[site]/about/contact` | **ISR** | `3600` | `getPage` + `listConfigs(group=site)` | `Page`、`Config` |
| `/[site]/departments` | **ISR** | `3600` | `listSites`（子站列表作为院系入口） | `Site` |
| `/[site]/faculty` | **ISR** | `3600` | `listArticles({channel:'faculty'})` | `Article` |
| `/[site]/admissions` | **ISR** | `3600` | `listArticles({channel:'admissions'})` | `Article` |
| `/[site]/admissions/undergraduate` | **ISR** | `3600` | `listArticles` 或静态 | `Article` |
| `/[site]/admissions/graduate` | **ISR** | `3600` | 同上 | `Article` |
| `/[site]/research` | **ISR** | `3600` | `listArticles({channel:'research'})` | `Article` |
| `/[site]/disclosure` | **ISR** | `3600` | `listArticles({channel:'disclosure'})` | `Article` |
| `/[site]/search` | **SSR** | `0` | `GET /api/search?site=&q=` | `Article` |
| `/[site]/sitemap` | **ISR** | `3600` | `getChannelTree` + `listArticles` | `Channel`、`Article` |
| `/[site]/[channel]` | **ISR** | `300` | 按 `Channel.type` 四分支（§4.3） | `Channel`、`Article`、`Page` |
| `/[site]/[channel]/[id]` | **ISR** | `300` | `GET /api/articles/[idOrSlug]` | `Article`、`Attachment` |

**渲染策略说明**：

| 策略 | 用于 | 理由 |
|---|---|---|
| **ISR**（默认） | 几乎所有内容页 | SEO 需要静态 HTML；`revalidate` 保证发稿后 5 分钟内可见 |
| **SSR**（`revalidate: 0`） | 仅搜索页 | 搜索词是请求参数，无法静态化 |
| **CSR** | 无 | 前台无纯客户端页面（评论提交走 `POST /api/comments`，不整页 CSR） |

**"发稿后立即可见"的两条保障**（A25 要求）：

1. 发布动作（Server Action）内部调用 `revalidatePath('/[site]/news')` 等受影响路径；
2. 提供 `POST /api/revalidate` 作为手工兜底（`14` §6.3）。

### 6.2 路由歧义兜底与后台加载态（U2 / U6 裁决）

#### U2 —— 歧义兜底（结论：加 `not-found` 兜底 + Vitest 单测）

`/main/news/123` 会同时匹配静态 `news/[id]` 与动态 `[channel]/[id]`。虽然 Next.js 静态段优先、理论上无歧义，但这是演示高频路径，故采取两层保障：

| 层 | 措施 |
|---|---|
| 兜底 | `(site)/[locale]/[site]/not-found.tsx` 与 `[channel]/not-found.tsx` —— 文章 id 不存在时渲染 404，**不回落到栏目列表**（避免"点进去看到列表"的迷惑） |
| 单测 | **Vitest 用例覆盖 `/main/news/123`**：断言该路径解析到 `news/[id]` 而非 `[channel]/[id]`；再断言 `/main/academic/123`（非保留 slug）解析到 `[channel]/[id]` |

> 实现方式：**T1.6 建骨架时先跑一次实测**，把结果固化为单测 —— 这样即使未来 Next 版本调整优先级，CI 会立刻报警。
>
> ⚠ **U2 断言必须打在拦截层重写后的内部路径上**（例 `/zh/main/news/123`，**4 段**），而非公开 URL（`/main/news/123`，**3 段**）—— `as-needed` 语义下 public URL 与内部路径不同。（T1.9 实测；见 `docs/00` §8 #45）
> 依据：App Router 的 pattern 是 `/[locale]/[site]/news/[id]`（4 段），而默认语言不带前缀的公开 URL 只有 3 段；next-intl 的拦截层内部重写补上 `[locale]` 段后才与 pattern 同形。

#### U6 —— 后台加载态与错误边界

| 文件 | 范围 | 内容 |
|---|---|---|
| `admin/*/loading.tsx` | **每段一个**（**15 个**；原 14 个 + M4 批次 2b 的 `recycle/loading.tsx`） | 表格骨架屏（shadcn `skeleton`）或表单占位 |
| `app/error.tsx` | **仅全局一个** | 统一错误界面 + "重试"按钮；**不做 14 份分段 error.tsx**（重复且无差异） |
| `(site)/**/loading.tsx` | 不单独加 | 前台走 ISR，首屏是静态 HTML，无加载态可言 |

### 6.3 子站首页模板（U7 裁决）

**结论：子站用简化模板，不复用主站模板。**

| 项 | 主站 `main` | 子站 `cs` / `ee` / `ba` |
|---|---|---|
| 焦点图轮播 | ✅ 全站轮播 | ❌ 去掉（或降级为单张院系横幅） |
| 学校要闻 | ✅ 全站要闻 | ❌ 替换为**本院新闻动态**（`/cs/news`） |
| 通知公告标签页 | ✅ 有 | ✅ 保留但只显示本院公告 |
| 院系/部门入口 | ✅ 有 | ❌ 去掉（子站自身就是院系） |
| 快捷入口 | ✅ 全套 | ⚠ 精简为 2~3 个 |
| 数据看板 | ❌ 不做 | ❌ 不做 |
| 实现方式 | `Site.template = "default"` | `Site.template = "department"` |

**理由**：子站的核心价值是"独立首页"（演示链路第 9 步）。若与主站模板完全一致，切换子站时看不出差别，这一步演示就失去意义。**代价**：多约半天工作量（第 2 周）。

## 7. MetadataRoute（A23）

### 7.1 `app/sitemap.ts` → `/sitemap.xml`

| 项 | 约定 |
|---|---|
| 数据源 | `Site(status=true)` → `Channel(status=true, type≠form)` → `Article(status='published', deletedAt=null)` + `Page(status='published')` |
| 输出 | 多站点合并为一个 sitemap；每条含 `url`、`lastModified`、`changeFrequency`、`priority` |
| URL 构造 | `NEXT_PUBLIC_SITE_URL` + `/[site]/...`；**非默认语言另出 `/en/...` 条目** |
| `changeFrequency` | 首页 `daily`、列表页 `daily`、详情页 `weekly`、单页 `monthly` |
| 规模保护 | 单站点文章 ≤ 100 篇，全站在 500 条以内，**不需要 sitemap index 分片** |

### 7.2 `app/robots.ts` → `/robots.txt`

| 项 | 约定 |
|---|---|
| 数据源 | `Config(group='seo')`，key 如 `seo.robots.disallow` |
| 默认内容 | `User-Agent: *` / `Allow: /` / `Disallow: /admin`、`Disallow: /api` / `Sitemap: {SITE_URL}/sitemap.xml` |
| 后台 | `/admin` **必须 Disallow**（避免管理页被索引） |

### 7.3 与"人性化站点地图页"的区别（易混淆）

| 项 | `/{site}/sitemap` 页面 | `/sitemap.xml` |
|---|---|---|
| 面向 | **人**（访客） | **爬虫** |
| 实现 | `(site)/[locale]/[site]/sitemap/page.tsx` | `app/sitemap.ts` |
| 内容 | 栏目树导航、可视化 | XML，含 `lastModified` |
| 二者关系 | 互不替代，**都要做**（A23） | 同上 |
