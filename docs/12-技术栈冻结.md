**七、⚠ 事故记录：`AUTH_SECRET` 曾生成"全零密钥"（H5，2026-10-02）**

| 项 | 内容 |
|---|---|
| **现象** | 首次生成密钥时打印出 `AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=`（44 个 `A`） |
| **根因** | 本会话是 **Windows PowerShell 5.1（CLR 4.0）**，`[System.Security.Cryptography.RandomNumberGenerator]::Fill(byte[])` **不存在**（该 API 为 .NET Core 2.1+；`GetBytes(int)` 亦不存在，只有 `GetBytes(byte[])`/`GetBytes(byte[],int,int)`）。调用失败 → 字节数组保持**全零** → `ToBase64String` 得到全 `A` 字符串 |

| **教训（写入文档的流程要求）** | ① **任何安全相关随机值必须验证随机性**（检查全零、重复字节数），不能只看"命令没报错"；② PowerShell 5.1 与 pwsh 7 的 .NET API 可用性不同，**生成密钥类脚本必须先用 `Get-Method`/`GetMethods()` 探测 API 是否存在**；③ 本会话后续所有脚本都需遵守该假设 |

**五、`pnpm --dir` 与 `-C` 的存在性（实测确认）**

在 pnpm 12.8.1 的 `dist/pnpm.mjs` 中：

```
{ name: "--dir <dir>", ... shortAlias: "-C" }
```

→ **`--dir <dir>` 与短别名 `-C` 均存在**。hook 采用 `pnpm --dir app exec lint-staged`：显式 `exec` 表示"运行 `app/node_modules/.bin` 下的本地二进制"，比裸命令更明确、不受脚本名冲突影响。

**六、⚠ 环境陷阱登记：PowerShell 5.1 读取 UTF-8 文件会误报 JSON 无效**

| 项 | 内容 |
|---|---|
| 现象 | `Get-Content package.json -Raw \| ConvertFrom-Json` 报 `传入的对象无效，应为":"或"}"`，且中文显示为乱码（如 `浠撳簱鏍癸細`） |
| 真相 | 文件**是合法 UTF-8 且无 BOM**（前 3 字节 `7B 0A 20`）；是 **PowerShell 5.1 默认按 CP936(GBK) 读取**导致解码错误 |
| 正确写法 | `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)` 或 `Get-Content $p -Encoding UTF8 -Raw` |
| 已有同类事故 | 与 §6.1 第 3 次记录的"UTF-16LE 重定向"是**同一类陷阱的两种表现**：PowerShell 5.1 的默认编码假设不可靠 |
| **流程要求** | 本项目所有读写 JSON/含中文文本文件的脚本，**必须显式指定 UTF-8**；校验脚本必须先确认文件编码 |

**三、`next typegen` 不清理 `.next/dev/types`（工作流摩擦点，已加防线）**

| 项 | 内容 |
|---|---|
| 报错 | `.next/dev/types/validator.ts:62:39 - error TS2307: Cannot find module '../../../src/app/test-login/page.js'` |
| 场景 | 删除一个路由（`test-login/`）后再跑 `typecheck` |
| 根因（时间戳取证） | `next typegen` **只重新生成 `.next/types/`**，**不清理 `.next/dev/`**（后者属 `next dev` 的产物）。而 `tsconfig.json` 的 `include` **同时收录** `.next/types/**/*.ts` 与 `.next/dev/types/**/*.ts` → **陈旧的 dev 路由类型被 `tsc` 编译**，指向已删除的文件 |
| 证据 | `.next/types/validator.ts`（14:20:03，typegen 产出）含 `test-login` **0 处**；`.next/dev/types/validator.ts`（14:02:33，dev 产出）含 **3 处**；`.next/dev/types/routes.d.ts` 含 **2 处** |
| **防线（用户裁决 ③）** | `typecheck` 改为三步：<br>`node -e "require('fs').rmSync('.next/dev/types',{recursive:true,force:true})" && next typegen && tsc --noEmit` |
| 为何只删 `.next/dev/types` 而非整删 `.next` | 该目录是**唯一**既被 `tsconfig.include` 收录、又不会被 `typegen` 刷新的目录；整删会连带丢弃 Turbopack 缓存（数 MB），拖慢下次 `pnpm dev` 首编译 |
| **⚠ npm script 内联引号的坑** | `node -e` 在 `package.json` 里必须转义为 `node -e \"...\"`，且内部字符串用**单引号**。若写成裸 `"`，JSON 合法但 shell 传参错乱。已实测该片段可直接执行（exit 0、无输出、目标目录确被删除） |
